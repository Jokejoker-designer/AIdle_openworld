## Product decision

AIdle will build the first detailed character and the first production-quality
construction block kit as one visual system. Character and environment must not
be developed as unrelated art tracks.

The shared system is a design and metadata language, not a rule that turns a
character into world-grid cubes.

## ARCHITECTURE LOCK

- Runtime remains Godot `4.3-stable`, 2.5D first, fixed/cozy camera language.
- Offline Block Assembly keeps the accepted Build Graph, socket, preview,
  validation, confirm, World Commit, persistence and compensation contracts.
- World construction uses grid/elevation/rotation and pair-compatible sockets.
- Character construction uses skeleton, bone attachment sockets, skin weights,
  rig and animation. Character joints never inherit world-grid snap semantics.
- Shared Character/Block DNA is limited to visual tokens, module identity,
  material slots, state variants, provenance, LOD and deterministic catalog
  metadata.
- Existing Character Foundry 1C identities and the accepted 28-record source
  manifest remain authoritative. No duplicate or invented identity is allowed.
- Existing `STATE_VARIANTS`, P1E world-profile palettes and Block-DNA contracts
  are reused; this work does not silently introduce DNA v1.2 or Tier 3 runtime.
- World Commit remains the only canonical local world mutator. Characters have
  no project, network, economy or World Commit authority.
- Red F01 remains a hard stop before networked work or shipping.
- No dependency install, credential, live provider, public network, Godot
  version change, push, deploy or publish is authorized by this direction.

Do not translate security, UX, or product recommendations into a deprecated
stack. Convert them into the current architecture.

## Shared visual DNA

The first character and block kit must share:

1. silhouette family and readable 2.5D proportions;
2. palette roles driven by the active world profile;
3. common material vocabulary for body, cloth, wood, stone, metal, glass,
   emissive accents and interactive highlights;
4. edge softness, bevel scale, surface detail density and value hierarchy;
5. modular IDs, provenance, material slots, LOD policy and `STATE_VARIANTS`;
6. preview/selected/invalid/confirmed visual states that remain readable at
   both accepted H1 viewport sizes;
7. accessibility constraints: contrast, reduced-motion compatibility and no
   critical information conveyed by color alone.

## First detailed pair

The first production slice is deliberately finite:

- one approved player-character record selected from the accepted Character
  Foundry catalog;
- one coherent modular character body/outfit kit;
- one skeleton and rig;
- idle, walk, turn, build/place, confirm and cancel animation set;
- one small construction family containing foundation, floor, wall, corner,
  door, window, roof, fence and one prop module;
- shared palette/material token pack;
- Godot integration proving the character can select, preview, rotate, place,
  confirm and cancel the matching block family;
- dual-resolution headed evidence showing the pair together in normal play.

## Sequencing lock

1. Finish H1 machine gate and Human five-minute gate.
2. Freeze a visual brief from existing Blueprint v1.1, P1E tokens and the
   accepted Character/Block registries.
3. Produce concept/turnaround and block-kit sheet together.
4. Build the detailed character, rig and minimal animation set.
5. Build the matching modular block family.
6. Integrate both through the already accepted P2E runtime.
7. Run visual, runtime, authority, persistence and Purple gates.
8. Expand only after the first pair passes Human visual review.

## Success condition

The player must look as though they belong to the same world they construct.
The slice fails if either side is merely a polished asset placed beside an
unrelated placeholder system.
