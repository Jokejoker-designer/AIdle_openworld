4 · Socket / connection logic

How the pieces above snap together, using only pairs confirmed directly against socket_types.json.

Known catalog gap (verified, not assumed) — four socket relationships in socket_types.json are declared one-directional even though the compatibility matrix marks asymmetry as an error: terrain_surface→prop_base, building_foundation→vertical_stack, wall_edge→window_opening, wall_edge→door_opening. This mockup follows the direction each pair already works in practice (foundation under wall, door/window into wall), it does not silently fix the schema. BLOCK-DNA-ADAPT owns the actual correction.

What this sheet is not

  • Not final 3D art, not a Blender/Godot asset. It is a proportion, palette and composition reference.
  • Not an authorization to dispatch UCBV-001. Directive 77 keeps UCBV-001 queued_not_authorized until the Human 5-minute gate on H1 passes and a new monotonic Codex directive opens it.
  • Not a claim that the catalog's socket data is production-safe. Section 4's asymmetric-pair note is real and still open in BLOCK-DNA-ADAPT scope.
  • Not a decision on which of the 28 Character Foundry records becomes the permanent player character — Nori-7 is used here only because it is record #1 of the cozy_cyber_pixel set and has a complete production-ready spec.
