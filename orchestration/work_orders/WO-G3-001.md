# Work Order — G3-001 AGM Onboarding Vertical Slice

Authority: `PATCH_DRAFT` for named writers; `VERIFY_ONLY` for reviewers.
Final acceptor: Codex.
Parent: the existing Grok Desktop conductor session only.

## Outcome

Integrate one deterministic Starter Realm transaction:

1. Create a World State Snapshot.
2. Receive a schema-valid AGM onboarding decision.
3. Show Companion text and quest state.
4. Convert the build proposal to the existing house recipe.
5. Preview through wireframe → hologram → materializing → complete.
6. Require explicit confirmation before executor/World Commit handoff.
7. Produce an execution receipt.
8. Demonstrate cancel and undo without canonical durable mutation.

This is a 2.5D, text-only, local Private Reality vertical slice. The live World
Commit service remains a handoff stub; do not invent server persistence or call
an external AI provider.

## Mandatory installed-subagent workflow

The parent must use all eight installed profiles under `.grok/agents/` and must
not perform a monolithic implementation itself.

### W0_VERIFY — no writes

- `schema`: validate Snapshot, Decision, World Prompt and receipt boundaries.
- `network`: audit that client/AGM cannot perform canonical durable mutation.
- `persist`: define deterministic cancel/undo evidence without implementing G4.

### W1_DOMAIN_PATCH — disjoint writers

- `core`: Starter Realm scene/UI wiring only.
- `manifestation`: preview lifecycle integration only.
- `companion`: text dialogue/quest presentation only.
- `asset`: house-recipe resolution and provenance validation only.

Each writer must claim exact files before editing. No two agents may write the
same file. If integration needs a shared file, reserve it for `executor` in W2.

### W2_EXECUTOR_INTEGRATE — single integration writer

- `executor`: own the transaction coordinator and end-to-end smoke only after
  W0/W1 handoffs exist. It must reuse existing modules and contracts.

### W3_PURPLE_REVIEW — verify only

The parent must select a non-writer subagent to challenge scope, authority,
cancel/undo behavior and test evidence. The parent collates results but may not
self-accept.

## Forbidden

- New top-level Grok/CLI session, nested grandchildren, or more than one parent.
- Edits to `tasks.json`, `codex_directive.json`, architecture or contracts.
- API SDKs, credentials, TTS/STT, voxel dependency, blockchain, push/deploy.
- Bypassing schema, preview, consent, executor handoff or World Commit boundary.
- `*-ACCEPT.json` or any worker-applied `ACCEPTED` state.

## Evidence required

- One valid MAF step contract per subagent.
- Parent dispatch map showing wave, authority and exact file ownership.
- End-to-end Godot smoke with clean log.
- Project validator.
- Deterministic complete, cancel and undo receipts.
- Adversarial review and remaining risks.

Finish as `REVIEW_REQUESTED`, update only `grok_status.json`, then stop for Codex.
