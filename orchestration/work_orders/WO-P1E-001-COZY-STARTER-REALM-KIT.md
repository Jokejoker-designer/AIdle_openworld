## Hard constraints from the library standard

- Templates and modules use Blender **linking/append through fixed code paths only**.
- The worker must **never open an arbitrary `.blend`**.
- Every library file must have a **SHA-256 recorded in the registry**.
- **No packed scripts, no auto-run handlers.** Workers keep running
  `--background --factory-startup --disable-autoexec`, as already verified in P0E.

## Guidance carried from the deep research reports

- **MultiMesh**: Godot has no per-instance frustum culling on MultiMesh.
  Partition scatter into sub-clusters per chunk region; never one MultiMesh for
  a whole biome.
- **Occlusion culling**: CPU-driven and best for indoor/room-heavy layouts. Use
  only on large authored blockers (house walls), not as the general outdoor
  optimization. Rely on visibility ranges, frustum culling and mesh LOD outdoors.
- **Material discipline**: one master stylized environment material family plus
  instance parameters. Do not let each module introduce unique materials.
- **Import presets**: modular static building / instanced foliage / HLOD proxy /
  collision-nav helper — see the synthesis doc's preset table.
- **Known lighting debt**: `ENV0-BACKLOG-PREVIEW-UNDEREXPOSURE` — the P0E probe
  render is heavily underexposed (luma max ~94/255). **Fix the lighting rig
  before authoring final materials**, otherwise every module will be colour-judged
  against a wrong exposure.
- **Known manifest debt**: `scene_manifest.json` currently emits null
  `output_class` and `blender_version`. Godot reads this manifest at intake —
  fill these before the Godot import step.
